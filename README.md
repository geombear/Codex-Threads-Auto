# Threads Studio

한국어 다계정 Threads 운영 도구입니다. Gemini 우선 생성, 공통 ChatGPT 구독 GPT 대체 생성, 외부 글 일괄 등록, 검토·예약·본문/답글 게시를 지원합니다.

## 실행

1. Node.js **24 LTS**를 설치합니다. 이 환경은 24.19.0에서 확인했습니다.
2. 처음에는 `install-studio.cmd`를 실행합니다. 이미 설치·빌드했다면 생략합니다.
3. `start-studio.cmd`를 실행하고 [작업실 열기](http://127.0.0.1:4310)를 엽니다.
4. 첫 화면에서 GEOM 또는 KYU를 선택하고 초기 PIN `0000`으로 로그인합니다. 상단 **PIN 변경**에서 현재 PIN과 새 숫자 4자리를 입력합니다.

터미널에서는 `npm ci`, `npm run build`, `npm start` 순서입니다. `npm test`로 모의 검증을 실행합니다. 라이브러리 버전은 package-lock.json에 고정되어 있습니다.
Gemini는 최초에 안정 버전 Flash를 선택하고 성공한 모델을 DB에 저장해 서버 재시작 후에도 재사용합니다. 모델 종료(404/410) 또는 모델·응답 스키마 호환성 오류 때만 목록을 갱신하고 대체 모델 하나를 시도합니다. 일반 인증 오류는 모델 교체 대상이 아닙니다. 일시적 오류와 잘못된 JSON/글자 수는 같은 모델로 1회 재시도합니다. 모든 실제 생성 시도는 한도에 포함되고, 최종 실패 시 GPT 대체 설정에 따라 이어가거나 글을 보류합니다.

## 시작 순서

- **계정 관리**: 이름, 카테고리 15종, 독자 10종, 게시 시간, 비율을 등록합니다. 말투는 편한 반말로 고정되며 금지 표현은 수정할 수 있습니다. 기본 주제 20개가 생깁니다.
- **연결 및 설정**: `.env.example`을 `.env`로 복사하고 `GEMINI_API_KEY`를 입력한 뒤 서버를 재시작합니다. GEOM과 KYU가 키 하나를 공유합니다. 환경 키가 없으면 기존 화면에 저장한 공통 키를 사용합니다. 연결 시험도 실제 API 요청이며 호출 한도에 포함됩니다.
- GPT 대체는 공식 Codex CLI의 ChatGPT 구독 로그인을 사용합니다. `codex login`으로 로그인하고 설정에서 GPT 대체를 켭니다. OpenAI API 키를 받거나 API 과금 경로로 전환하지 않습니다. 저장된 수동 모델 ID와 관계없이 CLI 기본 모델을 자동 사용합니다. CLI 기본 모델 변경을 반영하려면 Codex CLI도 최신 상태로 유지하세요. 구독 한도 소진 시 생성을 보류합니다.
- **주제 보관함**에서 소재와 확인된 근거를 등록합니다. 주제·근거가 부족하면 신규 생성을 보류합니다.
- **상품·제휴 링크**에서 정확한 상품, 옵션, 링크, 근거, 고지, 정책 URL, 유효기간, 미디어 사용 권한을 등록합니다. 제휴사 조건 확인은 운영자가 해야 합니다.
- **글 생성·예약 준비**에서 1~3일을 생성합니다. 새 계정은 검토 모드입니다. **콘텐츠 검토 → 승인·예약**으로 진행합니다.
- 외부에서 만든 글은 **콘텐츠 검토 → 작성한 글 일괄 등록**에 붙여넣습니다. 일상글은 `---` 한 줄로 구분합니다. 제휴글 JSON의 productId는 해당 상품의 실제 내부 ID가 필요합니다.
- **운영 재개**를 눌러 예약 처리를 시작합니다. 최초 상태는 전체 중지·모의 발행입니다.

## 실제 Threads 연결

Meta에서 Threads 앱과 해당 계정의 권한을 준비해야 합니다. 설정 화면에 앱 ID·시크릿을 저장하고 앱의 허용 리디렉션 주소를 `APP_URL/oauth/callback`과 정확히 맞춥니다. 공식 OAuth 로그인으로 계정을 연결합니다. 로컬 HTTP 콜백 허용 여부는 앱 설정에서 확인해야 하며, 필요한 경우 HTTPS 서버 주소를 사용합니다.

실제 게시를 하려면 `.env.example`을 `.env`로 복사해 `ALLOW_LIVE_PUBLISH=true`를 설정하고 재시작한 뒤, 해당 계정의 **실제 발행**을 켭니다. 기존 모의 예약은 실제 예약으로 자동 전환되지 않습니다. 먼저 새 콘텐츠를 검토하고 지정한 소량으로 연결을 확인하세요.

자동 운영을 켜면 다음 날의 빈 슬롯을 채우고 코드 검사를 통과한 글을 예약합니다. 최초 연결과 콘텐츠 품질 확인은 필요합니다. PC 종료·절전 중에는 작동하지 않습니다. 화면을 닫아도 서버가 실행 중이면 작업합니다.

## PC 상시 실행

- `서버상시실행.bat`: 서버가 종료되면 10초 뒤 다시 켭니다. 기록은 `logs/server.log`에 남습니다.
- `자동실행등록.bat`: 관리자 승인 후 작업 스케줄러에 `ThreadsStudio`를 등록합니다. PC가 켜지면 1분 뒤 로그인 없이 서버가 켜집니다. 창은 보이지 않습니다. `자동실행해제.bat`로 해제합니다.
- `서버끄기.bat`는 상시 실행도 멈춥니다. 다음 부팅 때는 다시 켜집니다.
- 절전 모드는 **안 함**으로 설정하세요. 절전·종료 중에는 게시하지 않습니다.

## 운영 및 복구

- **전체 중지**는 다음 외부 게시 요청을 막습니다. 이미 전송한 요청은 취소되지 않습니다.
- 인증 오류는 해당 계정을 중지시킵니다. 재연결하거나 토큰 갱신 후 설정을 확인합니다.
- 답글 실패 시 성공한 본문을 재전송하지 않습니다. 재시도 가능한 오류만 최대 횟수 내에서 처리합니다.
- **결과 확인 필요**는 자동 재전송하지 않습니다. 컨테이너 상태 조회는 가능하지만 게시 ID가 확정되지 않으면 계속 보류합니다. 현재 버전은 수동 게시물 연결과 완전한 자동 대조를 제공하지 않습니다.
- 놓친 본문 예약은 기본 30분까지만 처리하며, 초과하면 건너뜁니다. 답글 복구는 24시간 내로 제한합니다.
- 상품 근거 철회·만료는 승인본에도 발행 차단을 적용합니다. 상품 수정으로 예약글 링크가 바뀌지는 않습니다.

## 백업·복원

전체 중지 후 실행 창을 종료합니다. 로컬 저장소에는 한 프로세스만 접근해야 합니다.

`npm run backup`은 `backups/`에 암호화된 키 값, 계정·예약·이력을 포함하는 JSON을 저장합니다. **data/encryption.key 또는 ENCRYPTION_KEY는 백업 파일과 별도로 보관**하세요. JSON에도 글과 개인 경험 등 민감한 내용이 있으므로 외부에 공개하지 마세요.

복원 전 기존 `data/`를 별도 이름으로 보관하고, 원래 암호화 키를 새 `data/encryption.key`에 준비합니다. 빈 저장소에서 `npm run restore -- backups/파일.json`을 실행합니다. 전체 중지·계정 중지·자동 운영 해제 상태로 복원하며, 미완료 예약은 결과 확인 필요로 둡니다. 백업 이후 외부 게시가 있었는지 대조하기 전 재발행하지 마세요.

## 상시 서버

Node 24, 영속 디스크 또는 PostgreSQL, HTTPS 리버스 프록시와 프로세스 관리자를 준비합니다. `DATABASE_URL`, HTTPS `APP_URL`, `ENCRYPTION_KEY`, 필요한 `HOST`를 설정합니다. 신뢰하는 프록시 1개 뒤에서만 `TRUST_PROXY=true`를 사용합니다. 기본값은 로컬 127.0.0.1입니다. 공개 배포는 이번 작업에서 하지 않았습니다.

## 사용량과 한계

계정 N개는 기본 본문 3N/일입니다. 제휴글 하루 1개에 답글 1개이면 게시 요청은 최소 4N/일이며 컨테이너 생성·조회·토큰 갱신은 별도입니다. AI 생성 호출은 기본 3N/일, 대체·시험 호출은 추가입니다.

Gemini의 무료 여부는 모델·프로젝트 요금 설정에 달려 있습니다. 이 프로그램은 결제 설정을 바꾸지 않습니다. 코드의 일일 호출 제한과 공급자 측 쿼터를 함께 설정하세요. GPT는 ChatGPT 구독의 Codex 사용 한도를 사용합니다. 앱은 추가 크레딧을 구매하지 않습니다. 구독 계정의 별도 크레딧 설정과 한도는 공급자에서 확인하세요. 검증된 예약글은 생성 한도 소진과 별개로 처리됩니다.

현재 구현·검증 범위 및 미완료 기능은 [작업 상태](docs/PROGRESS.md), 외부 사양 확인은 [공식 자료](docs/SOURCES.md)를 확인하세요. 이 버전은 운영 기반 구현이며 원문 전체 19항목을 모두 완료한 제품은 아닙니다.

자동 선택은 짧은 글의 속도·안정성을 우선하는 규칙이며 모든 작업에서 최고 품질을 보장하지 않습니다. Gemini 실제 모델은 글의 provider 기록에 남고 GPT는 auto로 표시됩니다. 서비스 전체 장애, 로그인 만료, 구독 한도, CLI 자체 호환성 문제는 자동 복구를 보장할 수 없으며 해당 생성만 보류합니다.

참고: [Gemini 모델 목록](https://ai.google.dev/api/models), [OpenAI Docs CLI 명령](https://developers.openai.com/codex/cli/reference).
## 짧은 글 생성과 다시쓰기

- 본문은 공백 포함 150자 내외(80~220자)이며 AI 결과는 본문과 선택 답글만 받습니다. 작성 준비 7항목은 새로 생성하지 않습니다. 답글은 필요할 때만 100자 이내로 작성하고 광고 고지·링크는 서버에서 추가합니다.
- 대화 속 발견, 생활 장면, 작은 반전, 두 가지 비교, 짧은 메모, 공감 관찰, 작은 실천, 질문에서 시작의 8가지 구성을 섞습니다. 최근 두 구성은 피하고 최근 글 4개를 프롬프트에 전달해 도입·전개·결말을 반복하지 않게 합니다. 문체 품질과 완전한 반복 방지는 모델 결과에 따라 검토가 필요합니다.
- 생활정보를 대화와 장면으로 재구성할 수 있지만, 가상의 대사를 검증 근거나 실제 구매·사용 증언으로 만들지 않습니다. 주제 보관함의 검증된 근거는 그대로 적용됩니다. 자동 검색·사실 확인 기능은 아닙니다.
- Gemini 출력 상한은 1,024토큰입니다. 2.5 Flash는 추론 예산 0, 2.5 Pro는 128, Gemini 3는 low를 사용합니다. 다른 세대는 호환성이 확인되지 않은 옵션을 강제로 보내지 않습니다. [공식 추론 설정 문서](https://ai.google.dev/gemini-api/docs/generate-content/thinking)
- 글 생성은 순차 처리합니다. 같은 계정의 동시 생성·다시쓰기 요청은 잠금으로 충돌을 막습니다.
- 검토·보류 글에서 **AI 다시쓰기**를 눌러 수정 요청을 입력할 수 있습니다. 성공한 다시쓰기는 글당 5회까지이며 기존 글은 버전 기록에 남습니다. 실패하거나 이전 글과 거의 같으면 원문을 유지하지만 외부 호출은 사용량에 포함됩니다. 다시쓴 글은 자동 승인하지 않습니다. 예약 글은 먼저 보류해야 하며 게시 이력이 있는 글은 다시 쓸 수 없습니다.
- 전체 기본 한도는 300회, 계정별 50회입니다. 첫 재시작 때 종전 기본값 30/12만 300/50으로 올리고 다른 값은 유지합니다. 정확히 30/12를 직접 지정했던 경우와 종전 기본값은 구별할 수 없습니다. 이후에는 다시 자동 변경하지 않습니다.
- 오늘 사용량은 기존과 같이 UTC 날짜 기준이며 최초 생성·다시쓰기·연결 시험·재시도/대체로 구분합니다. 예전 기록은 분류 없음으로 표시합니다. 연결 시험은 글 전체 대신 짧은 JSON 응답을 확인합니다.
